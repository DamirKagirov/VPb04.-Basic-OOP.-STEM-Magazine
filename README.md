# VPb04. Подписки на журнал STEM

Учебная объектная модель системы управления подписками на научно-популярный
журнал STEM. Реализация соответствует описанию в [`architecture.md`](architecture.md).

Система позволяет:

- вести каталог продуктов (`8+` и `12+`) с пакетами из 6, 12 или 24 выпусков;
- заводить выпуски журнала и отмечать их вышедшими;
- хранить клиентов и историю их подписок;
- оформлять, продлевать, отменять и завершать подписки;
- покупать единичный выпуск, оформляя подписку на один месяц;
- сохранять и загружать все данные в формате JSON.

Оплата и доставка в модель не входят.

## Требования

- Python 3.10 или новее (проект проверен на Python 3.15);
- внешние зависимости не нужны — используется только стандартная библиотека.

## Быстрый старт

```powershell
# Создание виртуального окружения
python -m venv .venv

# Запуск демонстрации
.\.venv\Scripts\python.exe stem_journal.py
```

В Linux/macOS:

```bash
python3 -m venv .venv
./.venv/bin/python stem_journal.py
```

Демонстрация создаёт продукты, выпуски и клиентов, оформляет несколько подписок,
показывает продление, покупку единичного выпуска, отмену, завершение и обработку
ошибок, а затем сохраняет данные в `data/subscriptions.json` и загружает их
обратно.

## Классы

| Класс | Назначение | Основные методы |
|-------|------------|-----------------|
| `Product` | Продукт подписки: линейка, размер пакета, каталог выпусков | `create`, `update`, `add_issue`, `find_issue`, `issue_at`, `issues_from`, `issues_after` |
| `Issue` | Один выпуск журнала | `create`, `release` |
| `Customer` | Клиент и история подписок | `create`, `change_name`, `change_email`, `change_address`, `add_subscription`, `buy_issue` |
| `Subscription` | Подписка клиента на продукт | `create`, `create_single_issue`, `renew`, `cancel`, `close` |
| `JsonStorage` | Сохранение и загрузка JSON | `save`, `load`, `exists` |
| `Journal` | Фасад для работы с системой | `add_product`, `add_customer`, `subscribe`, `buy_issue`, `save`, `load` |

### Правила предметной области

- У продукта не больше одного выпуска в месяц, поэтому `add_issue` отклоняет
  дубликаты по году и месяцу.
- `Subscription.create` берёт первые `issue_count` выпусков каталога начиная
  с указанного месяца. Если выпусков не хватает на полный пакет, оформление
  не выполняется.
- `Subscription.create_single_issue` (или `Customer.buy_issue`) оформляет
  покупку одного конкретного выпуска как активную подписку на один месяц.
  Выпуск должен присутствовать в каталоге продукта; подписка хранит ссылку
  на него.
- `renew` добавляет следующий пакет строго после последнего назначенного
  выпуска. Если полного пакета нет, подписка не меняется.
- `close` разрешён только для активной подписки, все выпуски которой уже вышли.
- `cancel` сохраняет назначенные выпуски в истории.
- Подписки хранят ссылки на объекты `Issue` из каталога продукта, поэтому один
  выпуск может одновременно входить в подписки разных клиентов.
- После отмены или завершения подписки оформляется новая подписка.

## Формат JSON

Выпуски хранятся один раз — в каталоге своего продукта. Подписки ссылаются на
них по `issue_ids`, что позволяет восстановить общие объекты выпусков при
загрузке.

```json
{
  "version": 1,
  "saved_at": "2026-11-20T12:00:00",
  "products": [
    {
      "product_id": "PRD-001",
      "edition": "8+",
      "issue_count": 6,
      "issues": [
        {
          "issue_id": "ISS-001",
          "issue_year": 2026,
          "issue_month": 1,
          "status": "planned"
        }
      ]
    }
  ],
  "customers": [
    {
      "customer_id": "CUS-001",
      "name": "Анна Смирнова",
      "email": "anna@example.com",
      "address": "г. Москва, ул. Лесная, д. 7",
      "subscriptions": [
        {
          "subscription_id": "SUB-001",
          "product_id": "PRD-001",
          "issue_ids": ["ISS-001"],
          "status": "active"
        }
      ]
    }
  ]
}
```

Файл записывается атомарно: сначала во временный файл, затем заменяет целевой.
Идентификаторы новых объектов продолжают нумерацию после загрузки данных.

## Ошибки

Все ошибки предметной области наследуются от `StemJournalError`:

- `ValidationError` — некорректные входные данные;
- `CatalogError` — нехватка выпусков или нарушение целостности каталога;
- `StateError` — операция недопустима в текущем статусе;
- `StorageError` — ошибка чтения или записи JSON.
